# BAGULAS マイルストーン1 実装計画

## 絶対条件（違反は差し戻し）

- 解像度 160×144 固定。表示は整数倍スケールのみ（`imageSmoothingEnabled=false`）
- 4階調パレット固定（DMG緑）: `#0f380f #306230 #8bac0f #9bbc0f`（index 3=最暗〜0=最明の順は gfx.js で定義）
- **ロジック中の float 禁止**。座標・速度は 8.8 固定小数点の整数。除算は `>>`、乗算後は `>>8`。
  `Math.random / atan2 / sin / cos / tan / sqrt / floor` 禁止（`|0` と `>>` を使う）。
  例外: 描画直前の canvas 座標変換、`performance.now()` の時間累積のみ。
- スプライト: 画面内 **40個** / 横一列（同一 y 走査線）**10個** を JS 側でも遵守。
  超過分は描画しない＋スポーン抑制。点滅させない。
- 乱数は 8bit LFSR のみ（`src/rng.js`）
- 60fps 固定ステップ（アキュムレータ方式）。**catch-up 上限は 1**。
  重い場面では logic を間引かず、ゲーム全体が一緒にスローになる（実機GB風）。
  フレームスキップで弾だけワープさせるのは禁止。アキュムレータは 1 ステップ分でクランプする。
- 入力は押下フレーム内に反映。自機移動に慣性・加速のもたつきを入れない（即応最優先）
- ヒットストップは最大2フレーム。演出でゲームを止めない
- キャラクターは **16×16**（8×8タイル4枚のメタスプライト）。1体でスプライト4個・1走査線あたり2個を消費する
- グラフィックは 8×8 タイル。プログラム生成の仮タイルでよい
- ビルド不要の素の ES modules。npm / バンドラ / 外部CDN 禁止

## ファイル構成（確定・勝手に増やさない）

```
index.html
src/fixed.js     固定小数点・16方向テーブル・狙い判定
src/rng.js       8bit LFSR
src/input.js     キー入力（押下/トリガ）
src/tiles.js     仮タイルデータ生成（2bpp 8x8）
src/gfx.js       パレット・タイルアトラス・BG描画・OAM(スプライト上限管理)・文字描画
src/entities.js  固定長プール（自弾/敵/敵弾/エフェクト）
src/weapons.js   3武器の発射・更新

src/boss.js      ライバル中ボス

```

## 共通API（各ステップで固定。変更したい場合は停止して報告）

### fixed.js
- `const FP = 8;`
- `f(n)` 整数→8.8 (`n<<8`)、`toPx(v)` 8.8→画面px整数 (`v>>8`)
- `fmul(a,b)` = `(a*b)>>8`（32bit範囲を超えない値のみ扱う）
- `DIR16` : 長さ16の配列。各要素 `{dx, dy}` は 8.8 で長さ約256（1.0）のベクトル。
  index 0 = 上(0,-256) から時計回りに 22.5度刻み。**テーブルは定数リテラルで直書き**（生成に三角関数を使わない）
- `aim16(dx, dy)` : 差分（8.8でも生ピクセルでも比が同じなら可）から DIR16 の index を返す。
  実装は象限判定＋整数比較（`|dy|*TAN_TABLE[i] > |dx|*256` 形式）。三角関数禁止

### rng.js
- `seed(s)` / `rnd8()` 0-255 を返す 8bit LFSR（タップ 0xB8 相当）/ `rndRange(n)` = `rnd8()%n`

### gfx.js
- `initGfx(canvas)` : 160×144 のオフスクリーンを用意し、整数倍スケールで表示
- `clearFrame()` / `present()`
- `drawBG(scrollY)` : タイルマップ描画
- `pushSprite(px, py, tileId, flags)` : **画面px整数座標**。40個/10個/行 上限を内部で管理し超過は捨てる
- `pushMeta16(px, py, tileId0, flags, palInvert)` : 16×16 キャラを 8×8 タイル4枚で描く。
  **all-or-nothing**（4枚全部置けないなら1枚も置かない＝キャラが半分欠けない）。
  `palInvert` が真ならパレット反転で描く（被弾白フラッシュ用）
- `spriteBudgetLeft()` : 残りスプライト数（スポーン抑制の判定用。16×16 は 4 必要）
- `drawBGObject(px, py, tileId0)` : 障害物用。**スプライト枠を消費せず** BG レイヤに 16×16 を直接描く
  （実機では BG タイル書き換え相当。障害物でスプライト枠を潰さないための設計判断）
- `drawText(px, py, str)` : 数字＋英大文字のみ

### entities.js
固定長配列プール。`alive` フラグで管理、GC を発生させない（毎フレームのオブジェクト生成禁止）。
- 自弾 max 2 / 敵 max 12 / 敵弾 max 8 / エフェクト max 8 / 障害物 max 12 / スコアポップ max 4

### stages.js（6面＋周回を最初から表現できるデータ構造）
```
STAGES[6] = { id, name, tileset, sections: [...] }
section = { type: 'prelude' | 'main' | 'boss',
            length: <進行距離>,        // boss は 0
            waves: [ {at, formation, count, hp} ],
            obstacles: [ {at, kind, x} ],  // prelude は必ず空
            bossId: <number> }           // type==='boss' のみ
```
- ステージ5の boss rush は `sections` に boss セクションを複数並べるだけで表現する（ボス定義を再利用）
- 周回は `loop` カウンタを持ち、敵HP・弾速・密度に整数倍率を掛ける（`hp + loop`, `speed + loop*16` 等）
- M1 で中身を作るのはステージ1のみ。残り5面は id と名前だけの空データでよい

## ステップ分割

### Step 1: 基盤（fixed / rng / input / tiles / gfx / main ループ）
完了条件:
- `python3 -m http.server` で index.html を開くと 160×144（整数倍拡大）で荒野の道が縦スクロールする
- FPS が 60 固定ステップで動く（フレーム落ち時もロジックは固定）
- `node --check` が全 src/*.js で通る
- `DIR16` と `aim16` が実装済みで、簡易セルフテスト（コンソール）で 16 方向が期待 index を返す

### Step 1b: 追加要件反映（ループ上限1 / 16×16 メタスプライト）
完了条件:
- main.js の catch-up 上限が 1、アキュムレータが 1 ステップ分でクランプされる
- gfx.js に `pushMeta16`（all-or-nothing、パレット反転対応）と `drawBGObject` が入る
- tiles.js に 16×16 用の 4 枚組タイル（自機・敵2種・障害物3種）が入る

### Step 2: 自機・武器3種・自弾2発制限
完了条件:
- 十字/WASD で移動（画面外に出ない、**慣性なしの即応**）、Z/J でショット、X/K で武器サイクル、Enter でポーズ
- 自機は 16×16 メタスプライト
- 自弾は画面内2発まで。リボルバー(直進速)/鉄球(低速・貫通フラグ・横方向にわずかな加速で湾曲)/ダイナマイト(山なり=vy を毎フレーム減衰させ、一定距離で爆発エフェクト)
- HUD に現在武器を表示

### Step 3: 敵編隊・狙い弾・障害物・当たり判定・スコア/残機・手触り
完了条件:
- 進行距離ベースのスポーンテーブルで V字/縦列/蛇行 の3編隊が出る（敵は 16×16）
- 敵弾は `aim16` の狙い弾＋固定方向、画面内上限8発
- **敵の発射予備動作**: 発射の 20 フレーム前から構えモーション（点滅/パレット反転）を出し、見てから避けられる
- 障害物（岩・柵・サボテン）が本編セクションで流れてくる。接触ダメージ、岩とサボテンは破壊可・柵は不可
- 当たり判定: 自弾×敵、自弾×破壊可障害物、敵/敵弾/障害物×自機
- **手触り**: 敵被弾で1〜2フレーム白フラッシュ / 撃破で爆発アニメ＋破片＋スコアポップ /
  自機被弾で無敵約90フレーム＋点滅＋短いノックバック / ヒットストップは最大2フレーム
- スプライト上限に達したらスポーンを抑制する（`spriteBudgetLeft() >= 4` を確認してから 16×16 をスポーン）

### Step 4: ボス・ステージ構造・状態機械・周回
完了条件:
- `src/stages.js` が上記データ構造で 6 面分（1面のみ中身、5面は空枠）＋ boss rush 表現可能な形で存在
- ステージ1が **前哨戦（障害物なし編隊戦）→ 本編（障害物あり）→ ボス** の順で進む
- ライバルレーサーのボスが出現、専用攻撃パターン最低2種、HP制、予備動作あり、撃破演出＋スコア
- TITLE → PLAY → BOSS → CLEAR → （次ステージ／1面へ周回、loop+1で難度上昇）／ GAMEOVER → リスタート が Enter で一巡

### Step 5: SpriteLab パイプライン（動くものができてから）
完了条件:
- `tools/spritelab_gen.py` を `~/Playground/with-labyrinth/tools/spritelab_gen.py` から移植
- 16×16 ダウンサンプル＋4階調量子化を追加、出力は JS タイル配列に変換できる形
- `--dry-run` でプロンプトだけ確認できる。**クレジット消費のため実生成はユーザー承認後**
- プロンプトは `art/prompts/` に保存、共通 style_notes は1本に固定
- APIキーは環境変数 `SPRITELAB_API_KEY` のみ。引数・ログ・コードに書かない
